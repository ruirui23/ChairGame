# 高周波椅子取り 検知アプリ

競技「高周波椅子取りゲーム」用の補助ツール。可聴域外の高周波 BGM（16.0〜18.2kHz）が
**「鳴っているか / 止まったか」をマイクで機械検知**し、LAN 経由で iPhone に低遅延（画面点滅＋音）で伝える。
特に重要なのは **「鳴り止んだ瞬間」** の検知で、着席タイミング＝勝敗に直結する。

競技はレベル3（約12.3kHz以上）から本番（1〜2は人間が可聴）。設計の根拠となる実測データは
[`.docs/spec.md`](.docs/spec.md) に、音源解析スクリプトは [`scripts/analyze.py`](scripts/analyze.py) にある。

---

## 動作の仕組み

```
[運営PAスピーカー] ──16-18kHzの音──▶ [Mac（スピーカー横）]
                                          │ マイク → FFT → 16-18.2kHz 帯域エネルギー
                                          │ 閾値＋ヒステリシス＋保持時間で playing/stopped 判定
                                          ▼
                                   [Mac上のローカルサーバー] Node.js + WebSocket
                                          │ 状態変化を即ブロードキャスト（＋500ms心拍）
                             ┌────────────┴────────────┐
                             ▼                         ▼
                     [iPhone A（自分）]         [iPhone B（相方）]
                     画面点滅＋音（イヤホン）    画面点滅＋音（イヤホン）
```

**判定ロジック（`public/shared/detector-core.js`）**

1. `getUserMedia` でマイク取得（`echoCancellation/noiseSuppression/autoGainControl` を **false 固定**。ONだと高周波がノイズ除去されて検知不能）
2. `AnalyserNode` で FFT（`fftSize 2048` ＝窓約43ms、`smoothingTimeConstant 0`）
3. 16000〜18200Hz のビンの **dB をリニアに戻して合算** → 帯域レベル(dB)。ピーク検出ではなく帯域合算（音源は純音でなく音楽のため）
4. **ヒステリシス**：鳴り出すには `閾値＋ヒステリシス幅`、止めるには `閾値` を下回る（境界付近の点滅防止）
5. **保持時間**：停止60ms / 再開30msの継続で確定（チャタリング防止）
6. 状態変化時のみ WebSocket 送信 → 受信ページが点滅／音に反映

## 技術スタック

フレームワーク・ビルドツール無しの「素の Web 技術＋Node」構成。会場でオフライン動作。

| 領域 | 技術 | 備考 |
|---|---|---|
| サーバー | **Node.js**（標準 `http`）+ **`ws`** | 依存は `ws` のみ。静的配信は自作 |
| 音声解析 | **Web Audio API**（`AnalyserNode`）+ `getUserMedia` | ライブラリ不要 |
| 通信 | **WebSocket**（LAN内 `ws://`） | 状態変化を即時配信＋500ms心拍 |
| フロント | **素の HTML/CSS/JS**（ES Modules、ビルド無し） | |
| 描画 | **Canvas API** | スペクトラム表示 |
| 音声合図 | **Web Audio**（`OscillatorNode`/`GainNode`） | 440Hz持続音のゲート（方式B） |
| 永続化 | **localStorage** | 閾値・帯域・受信設定を保存 |
| 音源解析(開発) | Python + `numpy` + `soundfile` | `scripts/analyze.py` |

## 実装状況

### ✅ 実装済み
- **帯域エネルギー検知**（16-18.2kHz、FFT 2048、リニア合算）
- **ヒステリシス**（既定6dB）＋**保持時間デバウンス**（停止60/再開30ms）＝点滅・チャタリング対策
- **WebSocketサーバー**：静的配信＋全クライアント配信＋500ms心拍＋起動時にLAN IP出力＋トラバーサル対策
- **受信ページ**（iPhone）：
  - 既定＝**鳴っている間チカチカ＋440Hz持続音／止まったら暗転＋無音**（この急変が着席合図）
  - `合図:鳴音中 / 合図:停止時` の方向切替、画面・音の個別ON/OFF、デバッグ表示
  - **接続断の警告**（心拍が1.5s途切れたら表示）
- **キャリブレーション**：①環境ノイズ3秒 → ②音源5秒 → ③自動で閾値設定（ノイズフロアより十分上・音源より下、SNR警告付き）
- **入力クリップ検知**：入力ピーク(dBFS)表示＋クリップ警告（声の誤検知＝クリップ歪みを診断）
- **帯域プリセット**：`標準16k` / `声除外17k`（母音は16kHz以上ほぼ無音・音源は17-18kHzに残る）
- **スペクトラム表示**（10-20kHz、監視帯域＝緑線、停止境界＝赤線、再生境界＝橙線）
- 設定の localStorage 永続化

### ❌ 未実装（今後）
- iPhone単体検知フォールバック（要HTTPS）
- Screen Wake Lock の本適用 / PWA化（要HTTPS、または NoSleep.js）
- 練習モード（反応訓練・遅延慣れ）
- ヘテロダイン方式A（高周波を低周波化してイヤホンで聴く＝バット・ディテクター。有線前提の切り札）
- QRコード表示（現状はURL手入力）

## セットアップ & 使い方

```bash
npm install
npm start
```

起動するとコンソールに URL が出る（IPはネットワークにより変わる）：

```
検知ページ (Mac):   http://localhost:8080/detector.html
受信ページ (iPhone): http://172.20.10.2:8080/receiver.html
```

### Mac（検知）
1. **Chrome推奨**で `http://localhost:8080/detector.html` → 「マイク開始」→ マイク許可
2. 音源を鳴らし、スペクトラムの緑線の間に山が立つか確認
3. **キャリブレーション**：①静かにして環境ノイズ測定 → ②実際の音源（最弱の**レベル4**推奨）で音源測定 → ③自動設定
4. 声で誤検知する時は **入力ピーク**を確認（クリップしていればマイクを離す）／**「声除外17k」**を試す

### iPhone（受信）
1. 同じLANから `http://<MacのIP>:8080/receiver.html` → 「タップして開始」（音声アンロック）
2. 音源が止まると画面が暗転＋無音になる＝着席合図

### スリープ対策（重要）
`npm start` だけでは Mac はスリープし得る。検知が凍ると受信側は「鳴っている」のまま固まる（無言の故障）。

```bash
caffeinate -dimsu npm start   # 画面・システムのスリープを防いで起動
```

加えて **フタは開けたまま／電源接続／検知タブは最前面・可視のまま**（画面オフや裏タブだと `requestAnimationFrame` が間引かれ検知が止まる）。

## 実測で確認済みの設計根拠（レベル3・4）

`scripts/analyze.py` で運営の実ファイルを解析（48kHz・650.6秒）：

- 監視帯域 **16-18.2kHz は両レベルで有効**。レベル4は 15-16kHz が消えるがエネルギーが 17-18kHz に集中し捕捉可能
- 音楽と真の無音の差が **48〜53dB** と巨大 → **保持60msでも誤検知しない**ことを実証
- レベル4はレベル3より約9dB弱い → **キャリブレーションは最弱のレベル4で行う**
- 真の無音は既知の4区間（0:00 / 3:53 / 7:27 / 10:45）に集中。レベル4はそこで最長1.6秒に断片化（曲構造由来、ランダムではない）

---

## 精度を上げるコツ

1. **マイク（最大のレバー）**：内蔵マイクは15kHz以上で感度が落ちる。HF特性の良い外付けマイクを**スピーカー近く・人から離して**置く
2. **クリップ回避**：大音量の近接音はマイクを飽和させ、歪みの倍音が16-18kHzに漏れて誤検知。入力ピークで監視
3. **帯域を上げる**：声が問題なら「声除外17k」
4. **本番はSNRが良い**：スマホスピーカー＋近接声は最悪ケース。PA＋スピーカー横マイクでは桁違いに安定

## ネットワーク（本番）

会場のWi-Fiが不明なため**外部ネット非依存**。自分のiPhoneのテザリングをホストにする。

- テザリングは「**互換性を優先**」ON（2.4GHz、到達距離優先）
- iOSテザリングは接続機器が無いと自動オフ → 開始前にMacと相方を繋いで維持
- 自分のiPhoneは親機兼受信機。**満充電**に

## 既知の制約・注意

- **Bluetoothイヤホンは150〜300ms遅延**。**画面が本命、音は保険**。有線推奨（遅延~10ms）
- iOS単体検知・Wake Lock・PWAは **HTTPS必須**（現状HTTPのため未対応。必要時にローカルHTTPS(mkcert)化）
- 検知タブを裏に回す/画面オフにすると検知が止まる（rAF間引き）
- ブランチ：開発は `develop`、`main` はMVP時点
